# MAX-бот для обращений в службу безопасности

Разработал бота, через которого сотрудники, контрагенты и частные лица могут обратиться в службу безопасности. В MAX у них есть одна точка входа. Бот отправляет сообщение в служебный чат выбранного подразделения. Специалист видит обращение у себя в чате и может ответить заявителю через бота.

Рабочий бот прошёл модерацию MAX и был запущен на серверном ПК. Служба безопасности получила канал приёма обращений с распределением по пяти направлениям и обратной связью в том же мессенджере. Здесь доступна обезличенная версия на основе пакета от 2 ноября 2026 года.

## Как проходит обращение

1. Заявитель выбирает одно из пяти направлений. Это экономическая безопасность, безопасность магазинов, безопасность складов и логистики, информационная безопасность или обращение к руководству службы безопасности. Для каждого направления можно настроить отдельный чат и показать контакт подразделения.
2. Бот уточняет категорию заявителя и предлагает отправить сообщение анонимно или с обратной связью. Затем передаёт текст в выбранное подразделение и подтверждает отправку.
3. В режиме обратной связи бот запоминает связь между сообщением в служебном чате и заявителем. Специалист отвечает на исходное сообщение, бот доставляет ответ в личный диалог. При анонимной отправке бот передаёт категорию заявителя и введённый текст, а связь для ответа не сохраняет.

## Что я реализовал

Написал асинхронный клиент MAX API на Python и HTTPX, обработку событий и сценарий диалога с кнопками. Для получения событий предусмотрены long polling и webhook на FastAPI. В публичной версии бот принимает ответ только от разрешённого специалиста и ищет получателя по сохранённой паре «служебный чат и сообщение».

Подготовил поставку под Windows через PyInstaller с проверкой зависимостей и TLS командой `--check`. Обновление от 2 ноября включает переход на новый адрес API MAX и настройку доверия к сертификату. В журнале остаются запуск, отправка обращения, отправка ответа и краткая категория ошибки. Содержимое переписки, идентификаторы и токены исключены из этих записей.

### Проверка локально

```text
python -m pip install -e .
python -B tools/run_tests.py
python -B bootstrap.py --check
```

Достаточно Python 3.11 или новее. Тесты используют подставной HTTP-транспорт и проверяют 30 сочетаний направления, категории заявителя и режима обращения.

### Запуск с тестовым ботом

Скопируйте `.env.example` в `.env`. Укажите токен своего бота и пять `DEPARTMENT_CHAT_ID_*`. В `SPECIALIST_IDS` перечислите через запятую ID специалистов, которым разрешено отвечать. Для каждого направления можно задать `DEPARTMENT_CONTACT_*`. Запустите `python bootstrap.py`. По умолчанию используется long polling. Для webhook задайте `MAX_TRANSPORT=webhook`, `MAX_WEBHOOK_URL` с HTTPS и `MAX_WEBHOOK_SECRET`.

При обновлении с прежней одночатовой версии укажите прежний служебный чат в `DEPARTMENT_CHAT_ID_ECONOMIC_SECURITY`, чтобы ответы на ранее принятые обращения продолжили работать. Реестр связей хранится в `appeal_links.json` рядом с файлом пользователей.

### Сборка на Windows x64

```powershell
python -m pip install -r requirements-windows-build.txt
python -B tools/build_windows.py --output-dir releases/max-support-bot-windows-x64
```

Сборка на Python 3.12 формирует ZIP с EXE, шаблоном настроек и контрольными суммами SHA-256 исходников и исполняемого файла. Сборщик запускает EXE с `--check`.
