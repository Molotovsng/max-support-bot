# MAX Support Bot

Обезличенная версия проекта бота для приёма обращений в мессенджере MAX.
В основе — практический опыт разработки, запуска и сопровождения корпоративного бота.
Публичная копия содержит нейтральные тексты и вымышленные идентификаторы.

**Технологии:** Python 3.11+, asyncio, HTTPX, FastAPI, JSON, unittest.

## Задача и результат

Бот собирает обращения в одном служебном чате. Пользователь выбирает свою категорию
и режим: сообщение без обратного ответа либо диалог со специалистом через бота.
Ответ специалиста возвращается пользователю по сохранённой связи с исходным сообщением.

Это позволяет организовать единый канал обращений и переписку через бота.
Измеренная экономия времени и количественные показатели внедрения не заявляются.

## Возможности

- Разделение клиента MAX API, нормализации событий, сценария диалога и хранения.
- Асинхронные HTTP-запросы, polling и endpoint для webhook.
- Проверка webhook-секрета, TLS-сертификатов и параметров конфигурации.
- Ответы только от разрешённых специалистов в настроенном служебном чате.
- Маршрутизация по локальному реестру: текст и цитаты не задают получателя ответа.
- Обработка callback-кнопок, повторного запуска и сетевых ошибок.
- Ротация журналов; штатные записи об ошибках не включают содержимое сообщений.
- Автоматические проверки с поддельным HTTP-транспортом без рабочего токена.

## Проверка без подключения к MAX

```bash
git clone https://github.com/Molotovsng/max-support-bot.git
cd max-support-bot
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -e .
python -B tools/run_tests.py
python bootstrap.py --check
```

Для проверок не нужен `.env`. Тестовый инструмент отключает загрузку `.env`
и блокирует реальные HTTP-запросы. `--check` не запускает бота и не подключается к API.

## Подключение собственного тестового бота

1. Создайте бота в MAX и получите собственный токен.
2. Скопируйте `.env.example` в `.env`, заполните токен.
3. Замените вымышленные `DESTINATION_CHAT_ID` и `SPECIALIST_IDS` в `constants.py`
   идентификаторами своего тестового чата и разрешённых специалистов.
4. Запустите `python main.py`. По умолчанию используется polling.

Webhook включается через `MAX_TRANSPORT=webhook`; нужны собственный HTTPS-адрес
и `MAX_WEBHOOK_SECRET`. Сервис предоставляет `/health` и `/webhook/max`.

## Границы текущей версии

Состояние диалога хранится в памяти, реестры — в локальных JSON-файлах.
Нет надёжной очереди, общей дедупликации событий и транзакционного хранилища;
горизонтальное масштабирование не предусмотрено. После перезапуска диалог начинается заново.

Режим «анонимно» скрывает идентифицирующие поля в сообщении специалистам и не сохраняет
связь для ответа. Бот и платформа всё равно получают технический идентификатор пользователя;
это не гарантия полной анонимности. Личные сведения, написанные самим пользователем
в тексте, автоматически не обезличиваются.

Рабочие настройки, обращения, журналы, документы и данные организации отсутствуют.
Публичная версия предназначена для проверки кода и самостоятельного тестового запуска.
